# VK publisher AUQNI

`vk_publish.py` — отдельный скрипт на Python 3.10+ без внешних зависимостей.
Сообщество: **AUQNI | СМК**, `group_id=241580761`, `owner_id=-241580761`.
Скрипт VK работает отдельно от Telegram-пульта и `telegram_publish.py`.
Автоматическая отправка Пульта в VK не подключена.

Вход `--text-file`: UTF-8 текст/Markdown (передаётся буквально, без преобразования
разметки) либо JSON контент-завода, из которого читается `platforms.vk.content`.
Необязательный `--image`: PNG/JPG/JPEG до 10 MiB. Проверяются расширение и сигнатура,
но не полная декодируемость изображения. Текст обязателен, до 16384 символов.
Пути к входным файлам разрешаются относительно текущего каталога терминала.

По умолчанию и с `--dry-run` выполняется только локальная проверка: **ноль сетевых
запросов**, без загрузки фото, сохранения фото и публикации. Выводятся размеры,
тип изображения, наличие токена и редакционных маркеров `[уточнить]`, но не текст
поста и не секрет. Отсутствие токена не мешает проверке файлов. Dry-run не подтверждает
валидность токена, его права, готовность черновика к публикации или доступность VK.
Перед публикацией проверьте статус и содержание входного материала. Скрипт не
изменяет статус JSON. Рабочие посты в публичный репозиторий не включены.

Токен читается только из `VK_GROUP_TOKEN`: сначала окружение процесса, затем
пользовательская переменная Windows (`HKCU\Environment`) при отсутствии в процессе.
`.env` не читается и не изменяется. Секрет передаётся VK в теле HTTPS POST;
он не записывается в файлы и не выводится. Сырые ответы и исключения не печатаются.
Перенаправления HTTP запрещены; сетевые запросы имеют таймаут 30 секунд.

Реальная отправка требует отдельного явного флага `--publish`; без него скрипт
выполняет только локальную проверку. Отправку запускают только после проверки
конкретного материала и прав используемого токена.
Для текста используется `wall.post`; для изображения —
`photos.getWallUploadServer`, multipart-загрузка с полем `photo`,
`photos.saveWallPhoto`, затем `wall.post`. Версия API: **5.199**.

Ограничение: в официальной схеме VK эти методы отмечены как принимающие
пользовательский токен (`access_token_type: user`). Валидность ключа сообщества
не означает доступность публикации и загрузки фото. При ошибке 27 скрипт остановится
с пояснением; заменять токен или использовать другой источник автоматически не будет.
Источники: [wall](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json),
[photos](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json).

Автоматических повторов нет. После сетевой ошибки реальной отправки нужно проверить
стену вручную, прежде чем повторять: сервер мог принять пост до обрыва соединения.
Если сохранение фото прошло, а публикация не удалась, фото может остаться в VK;
автоматического удаления нет. Защиты от повторной ручной публикации нет.

Локальные тесты: `python -B -m unittest discover -s . -p test_vk_publish.py -v`
из каталога проекта. Все сетевые операции в тестах заменены заглушками,
настоящий токен тестам не нужен.
